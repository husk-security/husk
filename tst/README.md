# `tst/` is intentionally vulnerable. Nothing here is a bug.

This directory is husk's **fixture corpus**: a deliberately unsafe developer
machine, checked into the repository so husk's detectors can be tested
deterministically. Every dangerous-looking file here is dangerous on purpose. If
husk (or your own scanner, or a code-scanning alert) flags something in `tst/`,
that is the fixture doing its job.

**Do not report anything in this directory as a vulnerability in husk.** It is
explicitly out of scope in [SECURITY.md](../SECURITY.md). Real vulnerabilities in
husk itself go through the private channels described there.

> This file deliberately paraphrases the fixture payloads instead of quoting
> them. Quoting them here would make this README itself match husk's detectors,
> and a scanner that flags its own documentation is a scanner nobody trusts.

## The two files that look worst

Two fixtures reliably alarm anyone browsing the repository, so they are named
here explicitly.

### `tst/AGENTS.md` is a prompt-injection fixture

It is a two-line file whose entire content is a classic injection attempt: it
tells the reading model to disregard its prior instructions and to go read the
user's private SSH key. That text is the fixture. It exists so husk's
prompt-injection detector (`src/scan/checks/prompt_injection.rs`) has a real
payload to match rather than a placeholder.

⚠️ **`AGENTS.md` is the filename that agent harnesses load automatically.** If
you run an AI coding agent inside a clone of this repository, it may load that
file and be handed the injection. It is inert against a careful agent and it
does nothing by itself, but be aware it is there.

### `tst/.github/workflows/ci.yml` is a deliberately catastrophic workflow

It combines `pull_request_target`, `permissions: write-all`, an unpinned
`actions/checkout@v4`, a pipe from an external host straight into a shell, and
unescaped interpolation of a pull request title into a `run:` step. It is a
checklist of GitHub Actions anti-patterns in twelve lines, on purpose.

**It cannot execute.** GitHub only runs workflows from `.github/workflows/` at
the repository root; a workflow nested under `tst/` is never scheduled, never
triggered, and never granted a token. The host it fetches from is in the
reserved `.invalid` TLD and cannot resolve.

It exists so husk's CI-workflow detector has a positive case, and it is why husk
reports critical findings when you scan this repository against itself.

## What else is in here

- **Fake credentials.** AWS-shaped keys, tokens, and connection strings in
  dotfiles. All are documentation placeholders or syntactically valid nonsense.
  None authenticates to anything.
- **`ecosystems/`.** One small fixture per supported package ecosystem, used by
  the `ScanTarget` registry tests and the golden corpus
  (`tests/golden/targets-corpus.txt`). Manifests and lockfiles pin **old,
  knowingly vulnerable versions** so advisory matching has something to find.
  These pins are deliberate: never "upgrade" them, and dependency bots must not
  touch this tree.
- **Risky automation.** npm lifecycle scripts, git hooks, and shell snippets
  that do things a real install script should not.
- **Risky AI/MCP configuration.** `.mcp.json`, `.claude/`, `.vscode/` and
  similar files describing agent setups husk should warn about.
- **A path-length fixture** with a deliberately absurd directory name, used to
  verify that TUI and web layouts do not shift when a path is long.

## Rules for this directory

- Fixtures are **data, not code**. Nothing here is compiled, installed, or
  executed by the test suite. husk's scans are read-only by design: it parses
  these files statically and never runs them.
- **Nothing real goes in here.** No live credential, no real host, no personal
  data, ever, even expired or revoked. If you need a secret-shaped string, use
  an obvious placeholder in a documented example format.
- **Vulnerable pins stay vulnerable.** They are the test input.
- **Lockfile fixtures are generated by the real tool**, then pinned. Write a
  throwaway manifest with the versions you want, run the actual package manager
  (`--lockfile-only`/`--package-lock-only` and `--ignore-scripts`), and commit
  what it wrote. A hand-written lockfile drifts toward whatever the parser
  already accepts, so the test passes and the real format is never exercised.
- When you add a detector, add its fixture here and regenerate the golden corpus
  (`HUSK_UPDATE_GOLDEN=1 cargo test --no-default-features --test golden_corpus`),
  confirming the diff is exactly your new coordinates.

## Trying it out

Scanning this directory is the fastest way to see husk find things:

```sh
cargo run --no-default-features -- scan --offline tst --no-home-inventory
```
